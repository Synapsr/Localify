# Launch Profiles Are Resolved by Localify

A launch profile chooses where a service's variables come from at launch: local dotenv files, Proton Pass notes, or `pass://` references. Profiles are declared in `localify.toml` at the checkout root, not in the Localify config: the Localify config was root-owned under `/etc/localify` at the time, many services are inferred rather than stored, and the file only holds addresses (paths, vault names, note titles), so it can be committed and follows every worktree.

Localify reads the sources itself (`pass-cli item view`, in parallel, values kept in memory) and injects the variables, instead of prefixing the service command with `pass-cli run`. `pass-cli run --env-file` overwrites variables already exported in the shell, cannot read a note as a whole dotenv file without writing it to disk, and gives the service a non-terminal stdin and stdout. Owning resolution keeps one priority order: Localify runtime variables, then the shell, then `--env-file` and profile sources in order, then the framework's own files. Localify masks Proton Pass values in the service output itself.

A `danger = true` profile starts without a prompt in a terminal, since `--profile <name>` is already explicit, but requires `--confirm-profile <name>` without a terminal so automation cannot start it by accident. It fails when any source is missing, can stop the service after `max_duration`, and must be recorded by the daemon, which adds `X-Localify-Profile` to responses, feeds the desktop badge and writes start and stop audit lines without values. `default` can never be dangerous and the desktop app never remembers a chosen profile, so no relaunch lands on a dangerous profile by accident.

A first spike injected a styled banner into HTML: React 19 tolerated it during hydration, but a strict `style-src` CSP blocked its inline styles. The shipped browser indicator avoids that: the proxy only adds a same-origin `<script src>` right after `<head>` (reusing a CSP header nonce when present), and the script draws a draggable pill in a shadow root through the CSSOM after `load`, and prefixes the tab title. It is on by default for dangerous profiles and can be turned off with `browser_indicator = false`. `max_duration` stays optional and off unless a profile sets it.

Side effects of a local run on production data are switched off declaratively: `[profiles.<name>.env]` forces values over every source (dry-run flags, `CRONS_ENABLED = "false"`, neutral provider credentials). Blocking outbound traffic through a proxy was rejected, because most SDKs ignore proxy variables and it would give a false sense of safety.

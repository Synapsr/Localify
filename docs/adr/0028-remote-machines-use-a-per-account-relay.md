# Remote Machines Use a Per-Account Relay

Machines of one Localify account reach each other through one Durable Object per account in the existing Worker, which only relays. Every signed-in daemon with remote access holds one outbound WebSocket to it, accepted through the Hibernation API, so an idle connection keeps nothing in memory and costs no duration. Nothing on a machine listens for remote access. The contract is `docs/remote-machines.md`.

The relay routes frames by machine id and keeps no application payload: no history, no queue, no storage, no alarm. Each socket's attachment holds a bounded identity (machine id, connection id, version, an authorization deadline), and the object rebuilds its routing map from those attachments after it hibernates. A frame for a machine that is not connected is answered `peer_offline`, never kept. Inventory and output live on the machines, which are asked again for fresh state whenever a viewer looks or reconnects. Messages are capped at 64 KiB and inventory is paginated, so no single frame or snapshot grows with a large config.

Machine tunnels were the obvious alternative, since every machine already has `m-<id>.localify.dev`. They exist only while a machine serves public URLs (ADR 0025), each one past 1,000 costs $4.50 a month, and reaching a machine through one would mean an ingress listening for control traffic. A peer-to-peer link would need NAT traversal and a relay anyway. One object per account matches the unit of trust and billing, keeps the routing state small (ten machines at most), and lets a revocation close every socket of an account in one call.

Nothing streams while nobody looks. Inventory is sent only while a viewer watches, as versioned replacement snapshots skipped when unchanged. Output is followed only while its panel is open, and every watch or follow expires without renewal. Pings are answered by the platform's auto-response, which does not wake the object.

Each daemon paces everything it sends through one queue under the relay's per-socket budget, so concurrent snapshots and follows slow down instead of tripping it. Authorization is checked lazily on both ends of a frame, once a socket's one-minute authorization has passed, and a D1 failure drops the frame: the relay fails closed without a timer. Reconnects use exponential backoff with full jitter, honour server retry hints, spread out after a deploy, and never replay a control that had no answer. The connection limiters are load shedding, approximate and kept per location, behind a token-format check that keeps malformed requests away from D1; they do not cap how often a token is checked.

Durable Object duration dominates the cost while someone watches: an object is billed while it is active, and a viewer following output that never pauses could keep it active all the time. An hour of that costs about half a cent at today's prices, against $7.99 a month for Pro. An idle object whose sockets are all hibernatable incurs no duration charge, so an account nobody watches costs nothing. What a frame costs in active time is measured on staging by the relay PR before release, and an alert watches the namespace's monthly duration.

# Localify Cloud Is Paid and Billed Through Polar

Public URLs are a paid feature with no free tier. Pro costs $7.99 a month or $79 a year, and starts with a 7-day trial that asks for a card up front. It includes 2 serving machines and 10 public URLs. Add-ons, which ship after launch, are separate monthly subscriptions that need an entitled Pro plan: one more serving machine for $3, ten more URLs for $2. Signing in with GitHub stays free and gives an account, but without a plan no machine can create, claim or serve a public URL. The Team plan shows up on the pricing page only as "contact us".

The plan keeps the costs and the abuse in check. Each serving machine holds a Cloudflare tunnel, and past the 1,000 tunnels an account includes, each one costs $4.50 a month. A card and a GitHub account behind every URL make throwaway accounts expensive and leave someone to answer for each one.

Polar is the merchant of record, so it collects VAT and sales tax worldwide and Localify only receives payouts. Its fees, about 4% plus $0.40, cost more than Stripe's, but nobody has to file VAT returns in every country. Polar knows each customer by an external id, which is always the Localify user id. A client never chooses it. The Worker keeps a snapshot of each user's subscriptions in D1 and never calls Polar on the public path. Webhooks are verified on the raw body, recorded under their `webhook-id`, and only tell the Worker to refresh that user from Polar's subscription list. A refresh writes its snapshot only when no refresh that started later has already written one. Webhook delivery is therefore never the source of truth: a delivery that arrives late, twice or out of order changes nothing. A daily reconciliation catches any delivery that never came. The redirect after checkout grants nothing.

An **entitlement** is what an account may use: serving machines and public URLs. It comes from the plan's state (the lifecycle table in `docs/public-urls.md`) plus the add-ons, or from an **override**. An override is a row with explicit limits, a reason and an optional expiry, and it replaces what the plan gives. The people on the old allowlist get one through a single migration that runs once, so they keep their access without paying. A **ban** beats every grant. Banning someone refuses their API calls, takes their URLs offline and releases their tunnels.

Who may sign in and who may serve are two separate switches. `SIGNUP` is `allowlist` or `open`, and it only decides whether a GitHub account may finish a new sign-in. Entitlements are always enforced, in both modes. Moving back to `allowlist` blocks new sign-ins and leaves existing accounts and their plans alone. Paying customers therefore never lose access when sign-up closes again.

Trials are tracked against the GitHub identity as well as Polar's email and card checks. Once a user's subscription has had a trial, every later checkout for that user is created without one.

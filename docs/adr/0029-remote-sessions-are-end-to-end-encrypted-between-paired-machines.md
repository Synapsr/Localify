# Remote Sessions Are End-to-End Encrypted Between Paired Machines

What one machine sends another, its projects, its services' output and the controls it receives, is encrypted end to end from the first version. A dev server's output carries stack traces, tokens and customer data, and a control starts processes. Neither should depend on the relay, or on whoever controls Localify Cloud, staying honest.

Each machine generates an X25519 key pair locally on first need, keeps the private half in a 0600 file in its data directory next to `cloud.json`, and uploads only the public half. A machine's key is set once for its machine id. Names are not identities: a same-name sign-in gets a new machine id, so it inherits no trust and is paired again.

The cloud's key directory is never the root of trust, because whoever can edit it could substitute a key. Trust comes from a pairing ceremony: a person confirms on both machines the same 6-digit code, derived from the Noise handshake hash and two nonces exchanged by commit and reveal. Without the commitment, a relay in the middle could grind ephemeral keys until both codes matched; with it, an attempt succeeds once in a million and each attempt takes a person's click. Each machine then pins the other's key by machine id. Pairing is symmetric, and each machine's own settings decide what the other may see or do.

Sessions use `Noise_XX_25519_ChaChaPoly_BLAKE2s` through the `snow` crate. The first frame of a session names its purpose, pairing or session, so the responder knows which prologue to use. The prologue has an exact byte encoding of the protocol version, that purpose, the account, both machine ids and the session id, so a relay that rewrites the purpose only breaks the handshake. A handshake not complete within 30 seconds is dropped, and an encrypted heartbeat tells a peer that stopped answering from a relay that is still up. XX carries both static keys, authenticated, which pairing needs since neither side knows the other's key yet, and using it for every session keeps one code path. IK would save half a round trip once per session, with a first message that can be replayed and is sent before the responder is confirmed. `snow` is the most used Noise implementation in Rust (rust-libp2p uses it), exposes the handshake hash, and is pure Rust by default. Fresh ephemeral keys per session, per-direction nonces over one ordered connection, expiring controls and the expected run id give replay protection at each layer.

Permissions are checked on the target, from its own settings, on every request; the cloud only decides who may connect. Removing a machine from the account revokes its token and tells its peers to drop its pin. A lost key means a new sign-in and a new pairing. The limit is stated plainly: E2E does not protect against a compromised endpoint. A process running as the user on a paired machine can read its key and use its management socket, and so can see and do whatever that machine may.

# Public Endpoints Target Localify Domains

Public endpoints expose Localify local domains rather than their underlying route targets. This keeps project enablement, domain routing, path-based routes, local HTTPS behavior, and request diagnostics owned by Localify instead of duplicating those rules inside each public URL provider integration. Request logs remain scoped by the local domain, with public URLs treated as aliases or sources for that same local entrypoint. When traffic arrives through a public URL, Localify uses the local domain as the routing key while forwarding the public host to the upstream app by default. Localify sets the standard forwarded headers and its own local-domain header, but v1 does not expose custom header rewrite rules. V1 enriches the existing request logs with public URL, local domain, source, client, and access-protection outcome fields instead of building a full traffic inspector with bodies, replay, or header inspection. Custom public URLs require DNS verification before they become active, so DNS, certificate, and local app failures can be diagnosed separately. Public endpoints persist when the local connector is offline; runtime availability is represented as online or offline instead of deleting the endpoint. Disabling a project stops serving its public endpoints while preserving their cloud reservations. Wildcard public endpoints mirror Localify wildcard semantics: the root domain and one subdomain label are supported, while multi-level wildcard forwarding is out of scope. Custom wildcard public URLs require wildcard DNS records, and the root hostname needs its own DNS record when it should resolve too. V1 public endpoints attach only to configured local domains, not externally discovered domains such as Docker registrations. The desktop API exposes public endpoint details through dedicated public-endpoint commands, while domain list DTOs only carry lightweight public endpoint summaries for project-list display.

Amended by [ADR 0017](0017-public-traffic-reaches-upstream-with-the-local-host.md): upstream apps receive the local domain in `Host`, and the public host moves to `X-Forwarded-Host`.

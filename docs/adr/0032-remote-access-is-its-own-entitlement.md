# Remote Access Is Its Own Entitlement

Remote access is an explicit `remoteAccess` entitlement, next to serving machines and public URLs. Localify Cloud Pro includes it, and there is no free tier: the relay costs Durable Object time while someone watches, and a card behind every account keeps abuse expensive, as it does for public URLs (ADR 0024). It is never inferred from tunnel quotas, since an account can use remote access with no serving slot at all. An account links at most 10 machines, the limit on signed-in machines it already has.

An override replaces the plan entirely, so it states remote access itself, in a new `plan_overrides.remote_access` column. The overrides that exist were all granted by hand, so the migration gives them remote access. `cloud:admin override` grants it unless told otherwise. A ban removes it with everything else.

When an account loses remote access, through a lapse, a ban or an expiring override, or when a machine is removed from the account or signs out, three things happen. New operations are refused, at the connect route and at the lease route. The Worker pushes the revocation to the relay at once where it makes the change itself, which closes the sockets and so every session and output stream on them. Where it does not see the change, as with an override expiring or a `cloud:admin` command writing D1 only, authorization leases of about 60 seconds take over: the relay re-reads the account on the first frame after a socket's lease, and both endpoints renew theirs while a session is open and end it when renewal fails. Before each control, the target asks for a fresh lease and refuses when it cannot get one.

Nothing local stops. A lapse never stops a dev process, and the target's settings and pairings are kept for when the plan comes back. ADR 0027 still applies separately to public traffic. Removing a machine from the roster, signing out and billing keep working without the entitlement, so a person can always clean up and pay.

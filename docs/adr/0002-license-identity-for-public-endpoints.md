# License Identity for Public Endpoints

Persistent and custom public endpoints use the active Localify license as their cloud identity in v1, instead of requiring a separate user account. Localify Cloud can derive ownership, quotas, and contact email from the validated license record, while the desktop app keeps the product flow focused on license activation rather than signup or login. Public endpoint mutations require the cloud service to be reachable; offline state may be displayed from cache, but URL reservation, DNS verification, custom URL changes, and deletion are cloud-owned operations. Endpoints are owned by the license, but each endpoint is actively served by one selected local machine or connector at a time so multiple licensed machines do not accidentally expose different local projects through the same public URL. Deleted Localify-owned public URLs stay reserved for the same license identity for 30 days before becoming available again; custom public URLs are detached immediately and require DNS verification to attach elsewhere. Public endpoints are excluded from local settings export and import in v1 because ownership, reservation state, custom URL verification, and access-protection secrets belong to Localify Cloud. The desktop may keep a separate public endpoint cache outside `config.toml` for offline display and faster startup, but that cache is resynchronizable and must not store shared passwords or other public access secrets. Changes that affect a public endpoint relationship are cloud-first mutations; Localify must not write a local change and rely on later repair sync for endpoint ownership, URL reservation, or local-domain attachment. Local domain rename or delete actions that would affect a public endpoint require Localify Cloud to be reachable and must ask whether to detach or delete the endpoint when applicable. Deleting a public local domain detaches its endpoint by default, preserving cloud reservations; deleting the endpoint and its public URLs is an explicit destructive option. Removing a local domain outside that cloud-aware flow does not delete its cloud endpoint; the next cloud sync can surface it as orphaned until the user resolves it. Public endpoint and public URL quotas are tracked separately from local project and local domain limits; wildcard endpoints and wildcard public URLs each count as one reserved item.

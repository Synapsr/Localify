# Public URL Access Protection

Access protection belongs to each public URL, not to the public endpoint, so the same local domain can have protected and unprotected public addresses. Protected public URLs support path-prefix access exceptions in v1, using Localify's existing path-prefix semantics, so webhook, OAuth callback, health check, or asset paths can remain reachable without duplicating endpoint connections. V1 exceptions are path-prefix allowlists only; method, header, token, and IP-based access rules are out of scope. Password-protected URLs use one shared password and a Localify password page with a browser cookie instead of HTTP Basic Auth, because the primary sharing experience is for browser users rather than only scripts. For wildcard public URLs, access protection applies to the whole wildcard URL; if one subdomain needs a different policy, it should be modeled later as a more specific exact public URL.

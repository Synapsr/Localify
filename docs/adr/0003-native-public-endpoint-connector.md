# Native Public Endpoint Connector

Public endpoints use a native Localify connector integrated with the Localify runtime instead of launching an external tunnel binary. This keeps endpoint availability, selected machine ownership, logs, lifecycle controls, and local-domain routing inside the same Rust-first product boundary that the desktop app already drives through `DesktopApi`. Enabled public endpoints reconnect automatically when the daemon starts; disabling an endpoint keeps its reservation while making it intentionally offline. Connector availability is distinct from local target reachability, DNS verification, and certificate readiness so Localify can diagnose public endpoint failures without collapsing them into a single "down" state. Endpoint creation is allowed even when the local target is not currently reachable; the public URL can be provisioned while Localify reports the target as unavailable until the dev server starts. Connectors authenticate with short-lived tokens scoped to the endpoint, machine, and cloud identity, rather than sending a long-lived credential over every connector session. Only the selected machine may actively serve an endpoint; switching machines is an explicit claim that replaces the previous connector session, and automatic daemon reconnects must not silently take over endpoints served by another machine. Endpoint runtime status and public URL provisioning status are modeled separately; UI presentation can be refined later without merging those concepts.

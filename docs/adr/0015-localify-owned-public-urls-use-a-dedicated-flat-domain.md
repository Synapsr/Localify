# Localify-Owned Public URLs Use a Dedicated Flat Domain

Localify-owned public URLs live under `localify.fyi`, not under `localify.dev`, which serves the website, checkout, and downloads. If they shared the product domain, one phishing report or Safe Browsing flag against a user's URL could block the whole site, and any user app could set cookies on `.localify.dev` that the website and other users' URLs would receive. Every URL is a single DNS label under the domain: `<slug>.localify.fyi` for an endpoint and `<label>--<slug>.localify.fyi` for a label under a wildcard endpoint. Cloudflare's free Universal SSL certificate covers `*.localify.fyi` one level deep, so single labels need no per-endpoint certificate and keep environment and branch names out of Certificate Transparency logs. The last `--` separates the wildcard label from the slug, so slugs cannot contain `--`. Labels can, because multi-service environment domains already use `service--environment`.

The domain was registered cheaply for personal use first and may change if public URLs get real users. The public base domain is therefore configuration in Localify Cloud and the daemon, not a literal in code, and a move must serve both domains for a while because it breaks every existing URL. `localify.fyi` should go on the Public Suffix List once Localify has enough users to qualify; the list rejects small projects and requires two years of registration remaining. Until then the domain serves nothing but public URLs, and Localify only sets host-only cookies on it.
